# agent Specification

## Purpose

После Встречи Spook запускает Codex по Скиллу Встречи и передаёт ему Транскрипт и Словарь терминов. Spook принимает Выжимку и Тему, сохраняет Заметку и охраняет Транскрипт (ADR-0004). Служба ведёт очередь и Журнал Агента.

## Requirements

### Requirement: Заметка завершённой Сессии встаёт в очередь Агента
После завершения Сессии с Репликами и успешного обновления раздела «Встречи» Spook SHALL поставить опубликованную HTML-Заметку в очередь Агента один раз. Сессия без Реплик или незавершённая публикация запуск исключают.

#### Scenario: После «Стоп» Агент запущен один раз
- **GIVEN** идёт Встреча, начатая 2026-11-06 в 14:02, распознана Реплика «Реплика.»
- **WHEN** пользователь нажимает «Стоп»
- **THEN** Агент вызван ровно один раз — для Заметки «2026-11-06 14-02 Встреча»

#### Scenario: Агент получает окончательное имя Заметки
- **GIVEN** идёт Встреча, во время Сессии введена Тема «Репликация в Raft»
- **WHEN** пользователь нажимает «Стоп»
- **THEN** Агент вызван для страницы «2026-11-06 14-02 Репликация в Raft» в Wisp, и имя Журнала Агента совпадает с именем файла опубликованной страницы без расширения

#### Scenario: Сессия без Реплик
- **GIVEN** идёт Встреча, звук распознан пустым текстом
- **WHEN** пользователь нажимает «Стоп»
- **THEN** Агент и программа уведомлений не вызваны, блок Агента на экране пуст

### Requirement: Агенты работают по одному
Агенты SHALL работать по одному, в порядке очереди: Заметка, ждущая своей очереди, показывает «в очереди», та, над которой идёт работа, — «работает». Автоматических повторов нет: неудачный запуск остаётся ошибкой, пока пользователь сам не запустит Агента заново.

#### Scenario: Вторая Сессия ждёт Агента первой
- **GIVEN** Встреча, начатая в 14:02, завершена, Агент работает над её Заметкой
- **WHEN** пользователь проводит вторую Встречу, начатую в 15:02, и нажимает «Стоп»
- **THEN** экран показывает «работает» для `2026-11-06 14-02 Встреча` и «в очереди» для `2026-11-06 15-02 Встреча`
- **AND** Агент вызван сначала для первой Заметки, потом для второй, обе доходят до «готово»

### Requirement: Обёртка запуска и ограничение времени
Запуск SHALL ограничиваться временем из настройки `[agent] timeout_minutes` (по умолчанию 15 минут): Агент, работающий дольше, останавливается, и исход — ошибка «Превышено время: Агент работал дольше N мин». Команда из настройки `[agent] wrapper` SHALL ставиться перед программой Агента; `{timeout}` в ней заменяется на лимит в секундах.

#### Scenario: Агент работает дольше лимита
- **GIVEN** в настройках `timeout_minutes = 0.02`, Агент завис
- **WHEN** лимит времени истёк
- **THEN** Агент остановлен, исход — «ошибка» с причиной «Превышено время», та же причина записана в Журнал Агента

#### Scenario: Запуск через обёртку
- **GIVEN** в настройках `timeout_minutes = 2` и `wrapper = "env SPOOK_UNIT_LIMIT={timeout}"`
- **WHEN** Агент запущен
- **THEN** Журнал Агента начинается с `$ env SPOOK_UNIT_LIMIT=120 <программа Агента> --no-daemon exec `

### Requirement: Исход запуска — «готово» или «ошибка»
Spook SHALL принять ответ Codex после успешного завершения. Ответ — объект JSON, содержащий только строки `summary` и `topic`. Непустая Выжимка должна отличаться от прежней. Spook сам сохраняет её перед Транскриптом и только затем применяет Тему. При ошибке предыдущая Выжимка и Транскрипт доступны пользователю.

#### Scenario: Агент написал Выжимку
- **WHEN** Codex успешно возвращает новую Выжимку и Тему
- **THEN** свойства и Транскрипт сохранены, между ними новая Выжимка, исход — «готово»

#### Scenario: Агент завершился без Выжимки
- **WHEN** запуск завершается с ошибкой, файл последнего ответа отсутствует, либо в нём посторонние поля, пустая Выжимка или строка заголовка Транскрипта
- **THEN** исход — «ошибка» с причиной, прежние Выжимка и Тема сохранены

#### Scenario: Агент упал
- **WHEN** Codex пишет файл ответа и затем завершается с ошибкой
- **THEN** Spook показывает причину и сохраняет предыдущую Выжимку

#### Scenario: Повторный запуск не обновил Выжимку
- **WHEN** повторный запуск вернул прежнюю Выжимку
- **THEN** исход — «ошибка» с причиной «Агент завершился, но Выжимка не обновлена»

### Requirement: Журнал Агента открывается из интерфейса
Ссылка «Журнал» SHALL открывать Журнал Агента целиком как текст. Запрос Журнала Агента для неизвестной Заметки SHALL получать ответ 404, а имя, ведущее за пределы каталога, где лежат Журналы Агента, не обслуживается.

#### Scenario: Журнал Агента по ссылке с экрана «Сессия»
- **GIVEN** Агент отработал для Заметки `2026-11-06 14-02 Встреча`
- **WHEN** пользователь открывает ссылку «Журнал» в блоке Агента
- **THEN** ответ — текст (`text/plain`), равный Журналу Агента

#### Scenario: Журнала Агента нет и путь наружу
- **GIVEN** рядом с каталогом, где лежат Журналы Агента, лежит файл `secret.log` с текстом «не журнал»
- **WHEN** запрошены Журналы Агента для Заметок с именами `нет такой` и `../secret`
- **THEN** оба ответа — 404, текста «не журнал» в ответе нет

### Requirement: Уведомление о конце работы Агента
Когда Агент закончил, Spook SHALL отправить системное уведомление — вызвать программу из настройки `[programs] notify` (по умолчанию `notify-send`) с заголовком и текстом: «Выжимка готова» и имя Заметки либо «Ошибка Агента» и «<имя Заметки>: <причина>». Неотправленное уведомление SHALL записываться в журнал службы и не менять исход.

#### Scenario: Выжимка готова
- **WHEN** Агент написал Выжимку для Заметки `2026-11-06 14-02 Встреча`
- **THEN** программа уведомлений вызвана с аргументами «Выжимка готова» и «2026-11-06 14-02 Встреча»

#### Scenario: Ошибка Агента
- **WHEN** Агент упал с причиной «Codex завершился с кодом 1»
- **THEN** программа уведомлений вызвана с аргументами «Ошибка Агента» и «2026-11-06 14-02 Встреча: Codex завершился с кодом 1»

#### Scenario: Уведомление не отправилось
- **GIVEN** программа уведомлений завершается с ошибкой «служба уведомлений недоступна»
- **WHEN** Агент написал Выжимку
- **THEN** в журнале службы предупреждение, которое называет «Выжимка готова» и «служба уведомлений недоступна»; исход остаётся «готово»

### Requirement: Журнал службы о запусках Агента
В журнал службы Spook SHALL записывать начало и исход каждого запуска Агента: «Агент запущен: <Заметка> — <Скилл>, <модель>, <effort>» и «Агент закончил: <Заметка> — <исход>», для ошибки — с причиной.

#### Scenario: Неудачный запуск в журнале службы
- **GIVEN** в настройках Встречи модель `gpt-6.2-sol` и effort `medium`
- **WHEN** Агент для Заметки `2026-11-06 14-02 Встреча` упал
- **THEN** в журнале службы «Агент запущен: 2026-11-06 14-02 Встреча — spook-meeting, gpt-6.2-sol, medium» и «Агент закончил: 2026-11-06 14-02 Встреча — ошибка: Codex завершился с кодом 1»

### Requirement: Очередь Агента переживает перезапуск службы
После перезапуска службы опубликованные HTML-Заметки Встреч, ждавшие в очереди, SHALL запуститься в прежнем порядке. Прерванный запуск для Встречи SHALL стать ошибкой «Агент прерван перезапуском службы» с уведомлением без повторного запуска. Транскрипт его Заметки проверяется и восстанавливается, уже написанная Выжимка остаётся. Служба SHALL пропускать задачи прежних Заметок Markdown, в том числе Лекций. Содержимое прежних Заметок сохраняется.

#### Scenario: Перезапуск службы во время работы Агента
- **GIVEN** Агент работает над Заметкой `2026-11-06 14-02 Встреча`: написал Выжимку «Про тесты.» и переписал Транскрипт; Заметка `2026-11-06 15-02 Встреча` ждёт в очереди
- **WHEN** служба перезапущена
- **THEN** для первой Заметки показаны «Агент прерван перезапуском службы» и «Агент изменил Транскрипт — возвращён исходный.», в ней Выжимка и исходный абзац «14:02 Собеседники: Первая встреча.»; заново Агент для неё не вызван
- **AND** Агент вызван для второй Заметки и дошёл до «готово»
- **AND** уведомления: «Ошибка Агента» с текстом «2026-11-06 14-02 Встреча: Агент прерван перезапуском службы», затем «Выжимка готова» с текстом «2026-11-06 15-02 Встреча»

#### Scenario: В сохранённой очереди есть прежние задачи Лекций
- **GIVEN** до обновления в очереди остались Заметки Встреч и задачи `lecture`, одна из которых была в работе
- **WHEN** служба запускается после обновления
- **THEN** она восстанавливает задачи Встреч в прежнем порядке
- **AND** она не запускает Агента для старых Заметок Лекций и не переписывает их по сохранённой копии Транскрипта

#### Scenario: До перехода осталась задача для Markdown
- **GIVEN** в сохранённой очереди задача для `.md` и задача для HTML-Заметки Wisp
- **WHEN** служба запускается
- **THEN** она восстанавливает задачу для HTML, прежняя Заметка Markdown сохраняет путь и содержимое

### Requirement: Охрана Транскрипта
Spook SHALL охранять HTML-раздел «Транскрипт» опубликованной Заметки и восстанавливать его исходное содержимое при изменении. Для незавершённого запуска снимок HTML SHALL храниться временно в `.spook/` внутри Wisp. Очередь SHALL хранить только идентификатор снимка (`snapshot_id`, 32 шестнадцатеричных знака). Служба строит по нему путь внутри `.spook/` этого Wisp. После завершения или восстановления запуска снимок удаляется.

#### Scenario: Агент не тронул Транскрипт
- **WHEN** Агент написал Выжимку и не менял Транскрипт
- **THEN** на экране нет сообщений о Транскрипте, в Журнале Агента нет строки «Охрана Транскрипта»

#### Scenario: Агент переписал Транскрипт
- **GIVEN** на время работы Агента содержимое раздела «Транскрипт» изменено
- **WHEN** Spook завершает запуск или восстанавливает его после перезапуска службы
- **THEN** в Заметку возвращён исходный HTML-раздел с Репликами и Отметками, пользователь видит предупреждение
- **AND** в сохраняемых служебных сведениях вне Wisp нет текста Транскрипта

#### Scenario: Повреждённые сведения очереди
- **GIVEN** в очереди вместо идентификатора снимка записан посторонний путь
- **WHEN** служба восстанавливает прерванный запуск
- **THEN** файл по этому пути не читается, не изменяется и не удаляется

### Requirement: Стёртые заголовок и Заметка восстанавливаются
Если во время запуска Агента исчезла страница или повреждён раздел «Транскрипт», Spook SHALL восстановить Заметку из временного снимка в Wisp по прежнему адресу и сообщить о восстановлении.

#### Scenario: Агент стёр заголовок «Транскрипт»
- **GIVEN** перед запуском сохранён снимок HTML
- **WHEN** на странице утрачен раздел «Транскрипт»
- **THEN** по прежнему адресу снова доступна страница с исходным Транскриптом и свойствами Встречи

#### Scenario: Агент удалил Заметку
- **WHEN** опубликованная HTML-страница исчезает во время запуска
- **THEN** Spook восстанавливает Заметку с её свойствами и Транскриптом по прежнему адресу, пользователь видит сообщение о восстановлении

### Requirement: Заготовка Словаря терминов
Если файла Словаря терминов по пути из настроек нет, перед запуском Агента Встречи Spook SHALL создать заготовку с заголовком «# Словарь терминов» и пояснением, как его вести. Существующий Словарь терминов SHALL оставаться нетронутым.

#### Scenario: Словаря терминов нет
- **GIVEN** файла Словаря терминов нет
- **WHEN** Агент запущен для Заметки Встречи
- **THEN** файл создан, он начинается со строки «# Словарь терминов» и объясняет, что Агент сверяется с ним

#### Scenario: Словарь терминов уже есть
- **GIVEN** в Словаре терминов одна строка «- Kubernetes — кубер»
- **WHEN** Агент запущен для Заметки Встречи
- **THEN** содержимое файла не изменилось

### Requirement: Повторный запуск Агента для Заметки
Пользователь SHALL иметь возможность запустить Агента для Заметки заново — с моделью и effort, выбранными на этот запуск: Заметка снова встаёт в очередь, Выжимка пишется заново. Заметка, которая уже в очереди или в работе, второй раз не ставится: отказ «Агент для этой Заметки уже в очереди» или «Агент для этой Заметки уже работает». На экране «Сессия» Заметка показана один раз, с исходом последнего запуска.

#### Scenario: Заметка уже в работе
- **GIVEN** Агент работает над Заметкой
- **WHEN** приходит ещё одна команда запустить Агента для неё
- **THEN** команда отклонена с причиной, которая содержит «уже работает»; всего Агент вызван один раз

#### Scenario: После перезапусков Заметка показана один раз
- **GIVEN** для Заметки Агент отработал с исходом «готово»
- **WHEN** пользователь запускает Агента заново, и тот не обновляет Выжимку
- **THEN** блок Агента на экране «Сессия» показывает эту Заметку один раз — с «ошибка» и причиной «Агент завершился, но Выжимка не обновлена»

### Requirement: Для Заметки Встречи ведётся Журнал Агента
Журнал Агента SHALL храниться вне Хранилища. В нём сохраняются команда запуска, типы событий, код возврата, исход и причина сбоя. Служба SHALL исключать из Журнала текст Транскрипта, Выжимки и ответа Codex. Имя Журнала совпадает со стабильным именем HTML-файла без расширения. Повторный запуск для той же страницы SHALL дописываться в тот же Журнал, в том числе после изменения Темы.

#### Scenario: Журнал Агента после неудачного запуска
- **GIVEN** вывод Codex содержит тип события и текст из Встречи
- **WHEN** запуск завершается ошибкой
- **THEN** Журнал содержит команду, типы событий, код и причину завершения, текста Реплик, Выжимки и ответа Codex в нём нет

#### Scenario: Повторный запуск дописывается в тот же Журнал Агента
- **WHEN** первая Выжимка готова, повторный запуск выбранной моделью завершился с ошибкой
- **THEN** один Журнал Агента содержит оба запуска по порядку, их модели, effort и причины ошибок

### Requirement: Словарь терминов и списки заметок для Агента Встречи
Spook SHALL передать Агенту через стандартный ввод выбранный Скилл, дату, имеющуюся Тему, Транскрипт, Словарь терминов и названия связанных страниц из индекса Wisp с их относительными HTML-адресами. Содержимое соседних страниц и сама обрабатываемая Заметка в списке отсутствуют.

#### Scenario: Имена заметок без содержимого
- **GIVEN** в индексе Wisp есть «План релиза», в Словаре терминов — «Kubernetes»
- **WHEN** работает Агент
- **THEN** во входе есть «Kubernetes», «План релиза» и относительный адрес этой страницы, текста соседней страницы нет

### Requirement: Агент Встречи запускается одним вызовом Codex
Spook SHALL запускать `[programs] codex` напрямую в режиме `exec`, один раз на Заметку из очереди, по выбранному Скиллу. Аргументы запуска содержат явные модель и effort. Конец работы определяется по коду возврата, сообщениям Codex и проверенному структурированному ответу.

#### Scenario: Параметры по умолчанию
- **WHEN** Встреча завершилась и очередь запускает Агента
- **THEN** Codex запущен с `--model gpt-6.2-astra` и `model_reasoning_effort="high"`, итог запроса имеет заданную Spook схему

#### Scenario: Заметка из старой очереди
- **GIVEN** для опубликованной HTML-Заметки сохранена задача с прежней моделью `opus` и effort `medium`
- **WHEN** служба восстанавливает очередь
- **THEN** один запуск Codex получает модель `gpt-6.2-astra` и effort `high`

### Requirement: Изолированный запуск Codex
Spook SHALL запускать Codex в отдельной временной папке. Профиль разрешений запрещает модели доступ к файловой системе, команды, подключение приложений и MCP. Пользовательские настройки, хуки и AGENTS.md не попадают в контекст. Для сверки написания публичного термина допускается встроенный поиск Codex по индексу.

#### Scenario: У пользователя есть собственные MCP и инструкции
- **GIVEN** в домашней папке установлены дополнительные Скиллы, MCP и AGENTS.md
- **WHEN** Spook вызывает Codex
- **THEN** модель получает выбранный Скилл и сведения Встречи, без пользовательских инструкций и средств чтения домашней папки

#### Scenario: В Реплике названа команда
- **WHEN** Транскрипт содержит команду, путь к домашней папке или обращение к MCP
- **THEN** они передаются только в поле Транскрипта и не исполняются

### Requirement: Применение Темы из ответа Codex
Spook SHALL принимать предложенную Тему только для Заметки без Темы и только вместе с корректной Выжимкой. Очищенная Тема SHALL появиться на странице, её адрес сохраняется.

#### Scenario: Написавший Выжимку Агент предложил Тему
- **GIVEN** опубликована Встреча без Темы
- **WHEN** Codex возвращает Выжимку и Тему «Репликация в Raft»
- **THEN** в заголовке и поиске Wisp видна новая Тема, прежний адрес открывает тот же Транскрипт и новую Выжимку

#### Scenario: Пользователь уже задал Тему
- **WHEN** Codex вернул другую Тему для Заметки с Темой
- **THEN** Выжимка обновлена, Тема пользователя сохранена

#### Scenario: Во время Сессии выбран другой корень Wisp
- **WHEN** после завершения Встречи Codex прислал Тему для её Заметки, а в настройках уже другой корень Wisp
- **THEN** Spook обновляет опубликованную страницу в прежнем Wisp. Адрес Заметки и её Журнал Агента сохранены

### Requirement: Команда `spook topic` для завершённой Заметки
Команда `spook topic <Заметка> <Тема…>` SHALL задать Тему завершённой Заметке без Темы, вывести прежний путь к опубликованной HTML-странице и завершиться с кодом 0. Применяются очистка Темы и ограничение в 80 знаков. Слова можно передавать отдельными аргументами.

#### Scenario: Пользователь называет Заметку без Темы
- **GIVEN** опубликована Встреча без Темы
- **WHEN** пользователь вызывает `spook topic "<путь к HTML-Заметке>" "Репликация в Raft"`
- **THEN** на странице видна Тема «Репликация в Raft», команда печатает прежний путь, код 0

#### Scenario: Тема очищается
- **WHEN** Тема передана как ` Raft:<табуляция>"репликация" <журнала>/логов? #1 *|\ `
- **THEN** Заметка названа «2026-11-06 14-02 Raft репликация журнала логов 1»

#### Scenario: Длинная Тема отдельными словами
- **WHEN** Тема передана отдельными словами: Распределённые системы — консенсус, репликация журнала, снимки состояния, перевыборы лидера и членство в кластере
- **THEN** Заметка названа «2026-11-06 14-02 Распределённые системы — консенсус, репликация журнала, снимки состояния, перевы»

#### Scenario: Тема повторяет имя другой Заметки
- **GIVEN** в Wisp есть страница «2026-11-06 14-02 Raft» и Заметка Встречи без Темы
- **WHEN** пользователь задаёт второй Заметке Тему «Raft»
- **THEN** обе страницы читаются по прежним адресам, первая сохранила имя и содержимое

### Requirement: Отказы команды `spook topic` для страниц Wisp
Команда `spook topic` SHALL отклонять рабочую Заметку идущей Сессии, Заметку с Темой, пустую Тему, отсутствующий файл, старый Markdown, файл вне `html/` выбранного Wisp, ссылку на другую страницу и чужую страницу Wisp. Причина пишется в поток ошибок, код завершения 1. Отказ сохраняет имя и содержимое страницы.

#### Scenario: Страница недоступна для изменения Темы
- **WHEN** пользователь вызывает `spook topic` для рабочей Заметки, отсутствующей страницы, ссылки, страницы вне Wisp, старого Markdown или чужой страницы Wisp
- **THEN** код 1, причина в потоке ошибок, никакая страница не меняется

#### Scenario: Тема уже есть или передана пустая Тема
- **WHEN** пользователь пытается изменить указанную Тему или задаёт Тему из одних пробелов
- **THEN** отказ называет причину, прежний адрес и содержимое Заметки сохранены

### Requirement: Отображение причин ошибки Codex без текста Встречи
Spook SHALL распознавать ошибки сети, лимита, входа в Codex и недоступной модели. При другой ошибке программа SHALL показывать причину с кодом завершения, если он известен. Произвольный вывод Codex может содержать Реплики, в Журнале Агента и уведомлении остаётся только распознанная причина или код.

#### Scenario: Недоступная сеть
- **WHEN** Codex сообщает об ошибке соединения
- **THEN** экран и Журнал Агента показывают «Нет сети»

#### Scenario: Исчерпан лимит
- **WHEN** Codex сообщает об исчерпании лимита
- **THEN** экран и Журнал Агента показывают «Исчерпан лимит подписки»

#### Scenario: Ошибка программы или параметров
- **WHEN** Codex завершился с кодом 1 и записал в поток ошибок посторонний текст с Репликой
- **THEN** экран и Журнал Агента показывают «Codex завершился с кодом 1», Реплика отсутствует в причине ошибки, прежняя Выжимка сохранена

#### Scenario: Недоступна выбранная модель
- **WHEN** Codex сообщает, что указанная модель не поддерживается
- **THEN** пользователь видит причину «Выбранная модель Codex недоступна»

#### Scenario: Требуется вход
- **WHEN** Codex сообщает об ошибке авторизации
- **THEN** пользователь видит причину «Требуется вход в Codex»
