# Агент — фоновый запуск Claude Code по Скиллу, а не запрос к LLM из приложения

После «Стоп» приложение один раз запускает Claude Code без диалога (`claude -p "/<скилл> <путь к Заметке>"`) и ждёт, пока тот закончит. Что входит в Выжимку, как работать и что Агенту позволено, записано в Скилле пользователя — по одному на вид Сессии; приложение выбирает только модель и effort, следит за запуском и охраняет Транскрипт. Так решил пользователь: качество Выжимки важнее изоляции — Агент должен разбирать искажённые места, искать термины в сети, а Заметку Лекции оформлять по правилам Вики.

## Considered Options

- **Один запрос к LLM из приложения: Транскрипт на вход, Выжимка на выход — отклонён.** Проще и предсказуемее, но такой запрос не ищет в сети, не читает соседние заметки и не строит страницу Вики, а формат Выжимки пришлось бы зашивать в приложение. Кроме того, запрос к API оплачивается отдельно от подписки, а `claude -p` по документации расходует обычные лимиты подписки.
- **Агент в изоляции — без сети и командной строки, пишет только в файл Заметки — отклонён.** Ограничения снижают качество: нельзя проверить термин в сети и выполнить шаги Вики (сборка страницы, проверка в браузере).
- **Другие модели с переключаемыми профилями (MiMo, локальные) — отклонены.** Пользователь оставил только Claude; работа Claude Code с чужими моделями по документации официально не поддерживается.

## Consequences

- У проекта три части: приложение, Скиллы `spook-meeting` и `spook-lecture`, вкладка «Лекции» в Вики.
- Права Агента — это `allowed-tools` в шапке Скилла и обычные настройки Claude Code пользователя; приложение их не дополняет, а урезает только запретами, которые важнее любых разрешений (`--disallowedTools`): правка `.claude/` рабочего каталога и Хранилищ (там настройки и хуки следующего запуска) и `_tools/`, `_templates/` Вики (иначе Агент переписал бы `wiki_html.py`, а затем запустил его). `spook-meeting` читает и пишет в папке Встреч, читает Вики, ищет в сети; `spook-lecture` читает Вики и справочные файлы скилла `wiki`, правит только `lectures/` и `html/` Вики и запускает только `wiki_html.py` — браузер для проверки страницы запускает сам инструмент Вики (`check --render`), а не Агент: флаги Chrome позволяют запустить любую программу. Произвольной командной строки нет ни у одного Скилла; в режиме прав `default` Claude Code сам разрешает только читающие `ls`/`grep` внутри рабочего каталога запуска (проверено прогонами задачи 27), вне его — отклоняет.
- Остальное рабочее Хранилище, где лежат пароли, закрыто только тем, что запуск без диалога отклоняет всё неразрешённое. Это проверяется первой задачей — до кода, который запускает Агента.
- Транскрипт — недоверенный ввод: сказанное на встрече попадает к Агенту как текст, а у Агента есть сеть. Скилл обязан считать Транскрипт данными, а не указаниями; приложение сверяет Транскрипт после работы Агента и возвращает исходный, если тот изменён.
- Текст Транскрипта уходит в облако Claude. Звук не уходит никуда (ADR-0001).
- Агент зависит от окружения пользователя: подписки и её лимитов, хуков (при выключенном VPN запуск блокируется), версии Claude Code. При сбое Заметка остаётся с Транскриптом, интерфейс показывает причину и кнопку «Перезапустить»; автоматических повторов нет.
- Модель и effort выбираются в настройках приложения (по умолчанию Opus и high) и передаются флагами запуска, поэтому в шапке Скиллов они не указываются: `model` и `effort` в шапке перебивают флаги (проверено), и приложение перед запуском предупреждает, если они там есть. Opus с effort high заметно расходует лимиты подписки.
- Агенты работают по одному: два одновременных запуска делили бы лимиты и правили бы общий список страниц Вики.
- Скилл можно вызвать и вручную: `/spook-meeting <заметка>`.

## Проверено на практике

Проба 2026-11-07 на Claude Code 2.1.319 в чистом окружении через `systemd-run --user`, подробности и сырые выводы — `docs/research/headless-skill-probe.md`:

- Права с путями вида `Read(~/…/**)` и `Edit(~/…/**)` в шапке Скилла действуют при запуске без диалога: файл вне рабочего каталога, разрешённый правилом, читается; Заметка правится в режиме `default` без подтверждений.
- Чтение вне разрешённых папок отклоняется инструментом Read (`Path is outside allowed working directories`) и через Bash `cat`; запись снаружи отклоняется и в режиме `acceptEdits`. Содержимое чужого файла в вывод и Заметку не попадает. Инструментов Glob и Grep в этой версии нет — поиск по файлам возможен только через Bash, которого у Скиллов нет; записи `Glob`/`Grep` в `allowed-tools` ничего не дают.
- Блокировка хуком `UserPromptSubmit` завершает запуск с кодом 0 и `is_error: false`: признаки — `num_turns: 0`, `result` со строки `UserPromptSubmit operation blocked by hook:`, в `stream-json` — событие `informational` с `prompt_submit_outcome.kind: "blocked_by_hook"`.
- Отсутствие сети: около трёх минут повторов (`system/api_retry`), затем код 1, `is_error: true`, `api_error: "connection_failed"`.
- `model` и `effort` в шапке Скилла перебивают флаги `--model`/`--effort`.
- Завершение без Выжимки по выводу неотличимо от успеха — приложение проверяет саму Заметку.

## Не проверено

- Вид вывода при исчерпании лимита подписки: нарочно не вызвать. По документации — `rate_limit_event` со `status: "rejected"` и `errorCode: "credits_required"`, `api_retry` с `error: "rate_limit"`; текст `result` нужно записать из журнала при первом настоящем случае.
- Проба шла с проектным Скиллом (`<папка вида>/.claude/skills/`), а не с пользовательским в `~/.claude/skills/`; механизм загрузки общий.
