# Исследования

Сюда — только исследования, от ответа на которые зависит код или поведение приложения: замеры, сравнения вариантов, пробы. Порядок работы, скиллы и инструменты разработки сюда не входят.

## Issue

- Исследование ведётся по своему issue с меткой `research` (шаблон «Исследование»): вопрос, зачем он нужен и что считать ответом. Ветка — `<номер issue>-<slug>`, PR со статьёй закрывает issue через `Fixes`.
- Задачи, которые ждут ответа, заблокированы этим issue (blocked by); вопрос из интервью не исследуется по ходу, а становится таким issue.

## Где

- Итог — `docs/research/<slug>.md`, slug — по-английски через дефис, даже если скилл предлагает другое место.
- Черновики по ходу — `docs/research/<slug>/`. Итог записан — удали эту папку.

## Статья

- Заголовок — о чём исследование.
- Первый абзац — вопрос, зачем он нужен (какое решение или ADR проверяет) и дата. Сразу за ним — **Вывод:** в одно-три предложения.
- Дальше — как проверяли (условия, версии), результаты и ограничения.
- У каждого утверждения — источник, лучше первоисточник, или способ, которым это проверено.

## Связь с ADR

- Исследование отвечает на вопрос фактами; решение и его причины — в ADR по `docs/adr/README.md`.
- По итогам принят ADR — назови его в начале статьи; ADR ссылается на статью в `## Источники`.
- Вывод противоречит ADR — скажи об этом прямо.
