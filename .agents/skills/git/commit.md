# Коммит и push

Закоммить текущие изменения; push — только если пользователь о нём просил.

## Где выполнять

Работу выполняй в субагенте с чистым контекстом, не в текущем разговоре. Запусти одного субагента на той же модели, на которой идёт текущий разговор, с минимальным уровнем effort, и передай ему абсолютный путь к этому файлу (`<корень репозитория>/.agents/skills/git/commit.md`), рабочий каталог, пожелания пользователя к сообщению, нужен ли push, и название своей модели (для трейлера). Субагент выполняет шаги этого файла сам и других субагентов не запускает. Пользователю ответь итогом субагента дословно. Если запустить субагента нельзя — выполни шаги сам.

## Сообщение

По-английски. В `git log` смотри только на длину и структуру; имена API, путей и символов кода не переводи.

- Title: одна строка в повелительном наклонении («Fix null check in auth», не «Fixed…»).
- Body: пустая строка, затем список `-`, каждый пункт в повелительном наклонении, кратко, зачем.
- Trailer: пустая строка, затем `Co-Authored-By: <модель> <почта>` — модель агента, который делал изменения; её передаёт основной агент. Почта для моделей Claude — `noreply@anthropic.com`, для других — noreply-адрес их производителя.

```text
Fix race when refreshing a session

- serialize token rotation under a per-user lock
- add a regression test for parallel refresh

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

## Шаги

1. Параллельно: `git status`, `git diff`, `git diff --staged`, `git log -n 10 --oneline`.
2. Застейджить нужные файлы. Секреты (`.env`, ключи, credentials) не добавлять, при просьбе — предупредить.
3. `git commit -m "$(cat <<'EOF' ... EOF)"` с сообщением по разделу выше.
4. Hook отклонил — исправить и сделать новый коммит, не amend. Amend — только по явной просьбе или если hook поправил файлы после успешного коммита, а HEAD создан в этой сессии и не запушен.
5. Если нужен push: `git push`, без upstream — `git push -u origin HEAD`. Отклонён из-за расхождения с remote — не форсировать, кратко назвать причину.
6. `git status`. При успехе выполнить `git log -1 --decorate` (без tty decorate нужно указать явно) и ответить дословно его выводом, без своих комментариев. При ошибке — кратко причиной.
