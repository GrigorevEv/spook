# Pull request

Закоммить текущие изменения, запушь ветку и открой PR. Не мержить.

## Где выполнять

Работу выполняй в субагенте с чистым контекстом, не в текущем разговоре. Запусти одного субагента на той же модели и с тем же уровнем effort, что и текущий разговор, и передай ему абсолютный путь к этому файлу, рабочий каталог, пожелания пользователя и название своей модели (для трейлера). Субагент выполняет шаги этого файла сам и других субагентов не запускает. Пользователю ответь итогом субагента дословно. Если запустить субагента нельзя — выполни шаги сам.

## Шаги

1. Параллельно:
   - `git status`, `git diff`, `git diff --staged`, `git branch --show-current`, `git remote get-url origin`;
   - основная ветка: `gh repo view --json defaultBranchRef --jq .defaultBranchRef.name`, затем `git fetch origin <основная>`;
   - PR этой ветки: `gh pr list --head <ветка> --state all --json number,state,url`;
   - `AGENTS.md` в корне репозитория (`git rev-parse --show-toplevel`), если он есть: правила веток, коммитов и PR, команды проверки.
2. Остановиться, ничего не меняя, и кратко назвать причину, если:
   - `origin` не на github.com;
   - текущая ветка — основная, или HEAD отсоединён;
   - у ветки уже есть влитый или закрытый PR;
   - нет ни изменений, ни коммитов впереди `origin/<основная>`.
3. Если `AGENTS.md` называет команды проверки — запустить их. Упали — остановиться до коммита и показать, что упало.
4. Если есть изменения — коммит:
   - застейджить нужные файлы; секреты (`.env`, ключи, credentials) не добавлять, предупредить о них;
   - сообщение — по разделу «Сообщение» файла [commit.md](commit.md); модель для трейлера передаёт основной агент. Из коммитов ветки [merge.md](merge.md) потом собирает сообщение squash-коммита;
   - `git commit -m "$(cat <<'EOF' ... EOF)"`;
   - hook отклонил — исправить и сделать новый коммит, не amend.
5. Подтянуть основную: `git merge --no-edit origin/<основная>` (merge, не rebase — чтобы push обошёлся без force). Уже актуальна — дальше.
   - Конфликты — посмотреть, что меняла каждая сторона (`git log -p HEAD..origin/<основная>` и коммиты ветки), и разрешить так, чтобы сохранился смысл обеих; затем `git add` и `git commit --no-edit`.
   - Разрешение неочевидно (обе стороны по-разному переписали одно и то же, пришлось бы угадывать) — `git merge --abort`, остановиться и назвать файлы и причину.
   - Слияние что-то принесло — снова проверки из шага 3; упали — исправить отдельным коммитом, не вышло — остановиться и показать, что упало.
6. Push: `git push`, без upstream — `git push -u origin HEAD`. Отклонён — не форсировать, остановиться с причиной.
7. У ветки уже есть открытый PR — ответить его ссылкой и закончить.
8. Открыть PR:
   - изменения ветки целиком: `git log --format=%s origin/<основная>..HEAD` и `git diff origin/<основная>...HEAD`;
   - issue: ветка начинается с `<N>-` и issue `#N` открыт (`gh issue view <N> --json state`) — `Fixes #N`; если в пожеланиях сказано, что PR не закрывает issue, — `Refs #N`;
   - заголовок — как строка коммита, но про всю ветку; правила `AGENTS.md` важнее;
   - текст — по шаблону PR репозитория (`.github/pull_request_template.md`, `.github/PULL_REQUEST_TEMPLATE.md`, `docs/pull_request_template.md` или `pull_request_template.md` в корне): заполнить каждый раздел по его HTML-комментарию, сами комментарии убрать. Шаблона нет — два раздела: что сделано и как проверено;
   - язык текста — из шаблона или `AGENTS.md`, иначе язык пользователя; термины — из `GLOSSARY.md`, если он есть; без вступлений;
   - проверка — сессию, где делалось изменение, ты не видишь: бери тесты из диффа (какие добавлены или изменены) и итог прогона из шагов 3 и 5;
   - текст во временный файл (`mktemp`), затем `gh pr create --base <основная> --head <ветка> --title "..." --body-file <файл>`.
9. Ответить ссылкой на PR, без своих комментариев. При ошибке — кратко причиной.
