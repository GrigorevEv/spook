# Spook

Личный инструмент: слушает звук на компьютере, превращает его в текстовые Заметки, Агент пишет Выжимку.

- Пишешь текст, имена или issue — термины только из `GLOSSARY.md`, без синонимов; имена в коде — их английские имена оттуда. Появился новый термин или изменился смысл старого — внеси в словарь по правилам в его конце. Тексты интерфейса и документация — по-русски.
- Принимаешь решение, от которого зависит код или поведение Spook, — сверься с `docs/adr/`; если решение противоречит ADR, скажи об этом прямо. Новое такое решение запиши по `docs/adr/README.md`.
- Меняешь поведение — сначала изменение OpenSpec в `openspec/changes/<change>/`; текущие требования — `openspec/specs/`, правила к артефактам изменения — `openspec/config.yaml`.
- Перед правкой кода прочитай `CODING_STANDARDS.md`.
- Исследуешь вопрос, от ответа на который зависит код или поведение Spook, — по `docs/research/README.md`.
- Интервью (`grill-me`) — когда пользователь подтвердил итог, запиши новые термины, решения и исследования из него по правилам выше.
- Временное (черновики, снимки, прототипы, журналы проверок) — `tmp/<тема>/`, вне git. Скрипты, нужные после влития, — `scripts/`.
- `skills/` — Скиллы Агента, часть продукта (ADR-0003), а не скиллы агентов разработки.

## Запреты

- Звук живёт только в памяти (ADR-0001).
- `CLAUDE.md` не создавать: этот файл читают все агенты разработки, а при `CLAUDE.md` рядом Claude Code его не читает.

## Изменение: от ветки до PR

- Ветка — `<номер issue>-<имя>`, например `12-fix-pause-stop`; для изменения OpenSpec имя ветки — имя изменения.
- Готово, когда проходят быстрые тесты `uv run pytest -q` и `openspec validate --all --strict` — то же проверяет CI.
- Архивация изменения OpenSpec — последний коммит того же PR.
- Одно изменение OpenSpec — один issue, один PR с `Fixes #<номер>`. Issue требует нескольких изменений — разбей его на sub-issue.
